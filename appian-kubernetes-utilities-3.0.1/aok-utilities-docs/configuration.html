    Configuration Reference¶

    This document describes the complete schema for the config-values.yaml file used by aok generate. The config-values file is the single input that drives all generated deployment artifacts.

    File Structure¶

    The config-values file is a YAML document with three required top-level sections:

    repository:
  # Container registry settings
operator:
  # Appian Operator deployment settings
site:
  # Appian site deployment settings

    repository¶

    Registry and authentication settings for pulling Appian container images and Helm charts.

    Field Type Required Default Description
    appian string Yes — Container image registry path (e.g. my-registry.com/appian/images)
    helm string No — OCI Helm chart registry URL (e.g. my-registry.com/appian/helm)
    authSecretName string No — Name of an existing Kubernetes image pull secret
    authUsername string No — Registry authentication username (requires authPassword)
    authPassword string No — Registry authentication password (requires authUsername)

    Conditional Requirements¶

    • If authUsername is provided, authPassword must also be provided (and vice versa). These are used to generate a registry credential secret as part of the deployment guide.

    operator¶

    Settings for deploying the Appian Operator.

    Field Type Required Default Description
    topology string Yes — Operator deployment topology. Valid values: cluster-wide, main-and-site
    webhookCertModel string Yes — Webhook TLS certificate provisioning model. Valid values: cert-manager, ca-bundle
    version string Yes — Operator version tag (e.g. v0.194.0)
    namespace string No appian-operator Kubernetes namespace for the operator
    caBundleBase64Value string Conditional — Base64-encoded CA certificate bundle for webhook TLS

    Valid Values¶

    topology:

    Value Description
    cluster-wide Single operator instance managing all namespaces
    main-and-site Separate main and site operators; avoids cross-namespace permissions

    webhookCertModel:

    Value Description
    cert-manager Automated TLS via cert-manager (must be pre-installed in the cluster)
    ca-bundle Manually provided CA bundle embedded in operator Helm values

    Conditional Requirements¶

    • When webhookCertModel is ca-bundle, the field caBundleBase64Value is required. This value is the base64-encoded CA certificate that the operator uses to validate webhook TLS connections.

    site¶

    Settings for the Appian site deployment.

    Field Type Required Default Description
    namespace string Yes — Kubernetes namespace for the Appian site
    name string Yes — Appian site name (used in resource naming)
    appianPlatformCsHelmChartVersion string Yes — Version of the appian-platform-cs Helm chart
    class string Yes — Site sizing class. Valid values: x-small, small, medium, large, x-large
    highAvailability boolean No false Enable high-availability mode with multiple engine replicas
    sharedStorage boolean No true when HA Enable shared data PVC for the site
    rwxStorageClassName string Conditional — Kubernetes StorageClass name supporting ReadWriteMany access
    smtpAuthPassword string No — SMTP authentication password (written to passwords.properties)
    dataSources object No See below Database provisioning settings

    Valid Values¶

    class:

    Value Description
    x-small Minimal resource allocation for development/testing
    small Low resource allocation for small workloads
    medium Moderate resource allocation for typical production
    large High resource allocation for demanding workloads
    x-large Maximum resource allocation for large-scale production

    Conditional Requirements¶

    • When highAvailability is true or sharedStorage is true, the field rwxStorageClassName is required. This must reference a StorageClass that supports ReadWriteMany access mode.
    • When highAvailability is true and sharedStorage is not explicitly set, sharedStorage defaults to true (HA sites always require shared storage).

    site.dataSources¶

    Database provisioning settings. These control the generated SQL script for creating database schemas and users.

    Field Type Required Default Description
    dbType string No mysql Target database platform
    primarySchemaName string No appian_primary Primary database schema name
    primaryUsername string No PRIMARY_DB_USERNAME Primary database username
    primaryPassword string No YOUR_PASSWORD_HERE Primary database user password
    businessUsername string No — Business database username (triggers business DB provisioning)
    businessPassword string No YOUR_PASSWORD_HERE Business database user password
    businessSchemaName string No appian Business database schema name

    Valid Values¶

    dbType:

    Value Description
    mysql MySQL 8.x
    mariadb MariaDB 10.x+
    oracle Oracle Database
    postgresql PostgreSQL 12+
    sqlserver Microsoft SQL Server
    db2 IBM DB2

    Business Database Provisioning¶

    Business database statements are only included in the generated SQL script when businessUsername is provided. If businessUsername is set but businessSchemaName is omitted, the business schema defaults to appian.

    Storage Sizing by Class¶

    The generator automatically determines PVC storage capacity based on the selected site.class. The following table shows the storage values used for each sizing class:

    Class Shared Logs (non-HA) Shared Logs (HA) Shared Data (HA) Shared Data (non-HA)
    x-small 100Gi 200Gi 100Gi 50Gi
    small 100Gi 200Gi 100Gi 50Gi
    medium 150Gi 300Gi 200Gi 100Gi
    large 200Gi 400Gi 300Gi 150Gi
    x-large 200Gi 400Gi 300Gi 150Gi

    Notes:

    • The shared logs PVC (appian-shared-logs) is always generated. Its capacity is selected based on whether highAvailability is true (HA column) or false (non-HA column).
    • The shared data PVC (appian-shared-data) is only generated when sharedStorage is true. Its capacity is selected based on the HA mode.
    • Both PVCs use the ReadWriteMany access mode and reference the rwxStorageClassName value.

    Conditional Requirements Summary¶

    Condition Required Field
    operator.webhookCertModel is ca-bundle operator.caBundleBase64Value
    site.highAvailability is true site.rwxStorageClassName
    site.sharedStorage is true site.rwxStorageClassName
    repository.authUsername is provided repository.authPassword
    repository.authPassword is provided repository.authUsername

    Complete Example¶

    The following example shows all available fields:

    repository:
  appian: "my-container-registry.com/appian/images"
  helm: "my-container-registry.com/appian/helm"
  authSecretName: "regcred"
  authUsername: "AWS"
  authPassword: "REGCRED_PWD_VAR_PLACEHOLDER"

operator:
  topology: "cluster-wide"
  webhookCertModel: "ca-bundle"
  version: "v0.194.0"
  namespace: "appian-operator"
  caBundleBase64Value: "LS0tLS1CRUdJTi..."

site:
  namespace: "appian-site"
  name: "company-proj-dev"
  appianPlatformCsHelmChartVersion: "1.0.2"
  class: "medium"
  highAvailability: true
  sharedStorage: true
  rwxStorageClassName: "my.fileshare.sc"
  smtpAuthPassword: "my_smtp_pwd"
  dataSources:
    dbType: "mysql"
    primarySchemaName: "appian_primary"
    primaryUsername: "appian_primary_user"
    primaryPassword: "primary_password_here"
    businessUsername: "appian_business_user"
    businessPassword: "business_password_here"
    businessSchemaName: "appian"
