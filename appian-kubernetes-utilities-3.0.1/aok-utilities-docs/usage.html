    Usage¶

    aok generate¶

    Generate AoK deployment manifests and a step-by-step deployment guide from a config-values YAML file.

    aok generate -i <config-values.yaml> -o <output-dir> [--clean] [--debug]

    Options¶

    Option Short Required Description
    --input -i Yes Path to the config-values YAML file
    --output -o Yes Path to the output directory (created if it does not exist)
    --clean -c No Remove all existing files in the output directory before generating
    --debug -d No Enable verbose diagnostic output (sets log level to DEBUG)

    Minimal Config-Values Example¶

    The smallest valid input for a non-HA, cluster-wide deployment using cert-manager:

    repository:
  appian: my-registry.example.com/appian

operator:
  topology: cluster-wide
  webhookCertModel: cert-manager
  version: v0.194.0

site:
  namespace: appian-site
  name: my-site
  appianPlatformCsHelmChartVersion: "1.0.0"
  class: small
  highAvailability: false
  rwxStorageClassName: efs-sc

    Run:

    aok generate -i config-values.yaml -o my-output/

    Full Config-Values Example¶

    A complete input covering all optional fields — HA mode, CA bundle webhook model, registry credentials, database configuration, and SMTP:

    repository:
  appian: "my-container-registry.com/appian/images"
  helm: "my-container-registry.com/appian/helm"
  authSecretName: "regcred"
  authUsername: "AWS"
  authPassword: "REGCRED_PWD_VAR_PLACEHOLDER"

operator:
  topology: "cluster-wide"
  webhookCertModel: "ca-bundle"
  caBundleBase64Value: "LS0tLS1CRUdJTi..."
  version: "v0.194.0"
  namespace: "custom-operator-ns"

site:
  namespace: "appian-site"
  name: "company-proj-prod"
  appianPlatformCsHelmChartVersion: "1.0.2"
  highAvailability: true
  class: "medium"
  rwxStorageClassName: "my.fileshare.sc"
  sharedStorage: true
  smtpAuthPassword: "my_smtp_pwd"
  dataSources:
    dbType: "postgresql"
    primarySchemaName: "appian_primary"
    primaryUsername: "appian_primary_user"
    primaryPassword: "primary_password_here"
    businessUsername: "appian_business_user"
    businessPassword: "business_password_here"
    businessSchemaName: "appian_business"

    Output Directory Structure¶

    After running the generator, the output directory contains:

    my-output/
├── DEPLOYMENT.md                          # Step-by-step deployment guide
├── manifests/
│   ├── operator-values.yaml              # Operator Helm values
│   ├── site-operator-values.yaml         # (main-and-site topology only)
│   ├── cert-manager-selfsigned-cluster-issuer.yaml   # (cert-manager only)
│   ├── cert-manager-appian-op-webhooks-cert-secret.yaml  # (cert-manager only)
│   ├── appian-shared-logs-pvc.yaml       # Shared logs PVC
│   ├── appian-shared-data-pvc.yaml       # (shared storage only)
│   ├── appian-dbs-<dbType>.sql           # Database provisioning script
│   ├── passwords.properties              # SMTP credentials
│   └── appian-platform-cs-values.yaml    # Draft Helm values for site chart
└── dependencies/                          # Reserved for future use

    Files are generated conditionally based on your configuration:

    • site-operator-values.yaml — only when operator.topology is main-and-site
    • cert-manager-*.yaml — only when operator.webhookCertModel is cert-manager
    • appian-shared-data-pvc.yaml — only when site.sharedStorage is true

    Using --clean¶

    The --clean flag removes all existing files in the output directory before generating new ones. This is useful when you change your configuration and want to ensure no stale files remain from a previous run.

    Without --clean, existing files that match generated filenames are overwritten, but other files are left untouched.

    # First run — generates output
aok generate -i config-values.yaml -o output/

# Configuration changed (e.g. switched from cert-manager to ca-bundle)
# Use --clean to remove stale cert-manager manifests
aok generate -i config-values.yaml -o output/ --clean

    Using --debug¶

    The --debug flag enables verbose logging to stderr, showing each step of the generation pipeline. Useful for troubleshooting template rendering or validation issues.

    aok generate -i config-values.yaml -o output/ --debug

    Example debug output:

    DEBUG    aok_utilities.generator.core: Loading config from config-values.yaml
DEBUG    aok_utilities.generator.config: Validating schema...
DEBUG    aok_utilities.generator.config: Resolving defaults: dbType=mysql, namespace=appian-operator
DEBUG    aok_utilities.generator.storage: Loading storage values for class=small
DEBUG    aok_utilities.generator.template_selector: Selected 7 templates for rendering
DEBUG    aok_utilities.generator.renderer: Rendering operator-values.yaml.j2 → manifests/operator-values.yaml
DEBUG    aok_utilities.generator.renderer: Rendering DEPLOYMENT.md.j2 → DEPLOYMENT.md

    Error Output Examples¶

    Missing required fields¶

    $ aok generate -i incomplete.yaml -o output/

    ERROR    Configuration validation failed:
ERROR      • operator.topology: required field is missing
ERROR      • site.namespace: required field is missing
ERROR      • site.class: required field is missing

    Exit code: 1

    Invalid enumeration value¶

    $ aok generate -i bad-topology.yaml -o output/

    ERROR    Configuration validation failed:
ERROR      • operator.topology: invalid value 'single-node'; valid options are: cluster-wide, main-and-site

    Exit code: 1

    Invalid YAML syntax¶

    $ aok generate -i malformed.yaml -o output/

    ERROR    Cannot read config file: malformed.yaml: YAML syntax error at line 12: mapping values are not allowed here

    Exit code: 1

    File not found¶

    $ aok generate -i nonexistent.yaml -o output/

    ERROR    Cannot read config file: nonexistent.yaml: file not found

    Exit code: 1

    Conditional validation failure¶

    $ aok generate -i missing-ca-bundle.yaml -o output/

    Where missing-ca-bundle.yaml has operator.webhookCertModel: ca-bundle but no caBundleBase64Value:

    ERROR    Configuration validation failed:
ERROR      • operator.caBundleBase64Value: required because operator.webhookCertModel is 'ca-bundle'

    Exit code: 1

    aok visualize¶

    Read an Appian site YAML (the Kubernetes Custom Resource for an Appian site) and generate a PNG architecture diagram showing pods, PVCs, services, ingress, databases, and SMTP connectivity. A text-based resource summary table is also printed to stdout.

    aok visualize -i <site.yaml> [-o <output-path>] [--debug]

    Prerequisites¶

    The diagrams Python library renders diagrams via Graphviz. You must install Graphviz before running aok visualize:

    Platform Command
    macOS brew install graphviz
    Windows choco install graphviz or winget install graphviz
    Debian/Ubuntu sudo apt install graphviz

    If Graphviz is not installed, the command exits with a clear error message and installation instructions.

    Options¶

    Option Short Required Description
    --input -i Yes Path to the Appian site YAML file (Custom Resource)
    --output -o No Output path for the generated PNG (default: ./appian_site_visualisation)
    --debug -d No Enable verbose diagnostic output (sets log level to DEBUG)

    Note: The diagrams library automatically appends .png to the output path. If you specify --output my-diagram, the generated file will be my-diagram.png.

    Example Commands¶

    # Basic usage — generates ./appian_site_visualisation.png
aok visualize -i my-site.yaml

# Custom output path — generates ./docs/architecture.png
aok visualize -i my-site.yaml -o ./docs/architecture

# With debug logging
aok visualize -i my-site.yaml -o ./docs/architecture --debug

    Generating Input from Helm Values¶

    If you deploy your Appian site using the appian-platform-cs Helm chart, you can generate the input YAML with helm template:

    helm template my-site appian-platform-cs/ -f my-values.yaml > rendered-site.yaml
aok visualize -i rendered-site.yaml -o my-site-diagram

    This renders the Custom Resource manifest from your Helm values without applying it to a cluster.

    Output¶

    The command produces two outputs:

    1. PNG diagram — An architecture diagram saved to the output path (with .png extension). The diagram shows:
    2. All AoK component pods (zookeeper, kafka, searchServer, dataServer, serviceManager, webapp, httpd) with per-pod resource allocations
    3. PVC nodes for each component's storage
    4. Shared storage (health check logs, HA data)
    5. Service Manager engine breakdown per replica with per-engine resources
    6. K8s Service and ingress configuration (with platform-specific icons for ALB, Azure App Gateway, Nginx)
    7. Database nodes with type-specific icons connected via JDBC
    8. SMTP server connectivity

    9. A Users node showing site URLs

    10. Resource summary table (printed to stdout) — A tabular breakdown of CPU, memory, and storage allocations per component plus site-wide totals.

    Error Output Examples¶

    Graphviz not installed¶

    $ aok visualize -i my-site.yaml

    ERROR    Graphviz is required for diagram generation.
         Install Graphviz to generate diagrams:
           macOS:         brew install graphviz
           Windows:       choco install graphviz  (or)  winget install graphviz
           Debian/Ubuntu: sudo apt install graphviz

    Exit code: 1

    Input file not found¶

    $ aok visualize -i nonexistent.yaml

    ERROR    Cannot read config file: nonexistent.yaml: file not found

    Exit code: 1

    Invalid YAML syntax¶

    $ aok visualize -i malformed.yaml

    ERROR    Cannot read config file: malformed.yaml: YAML syntax error

    Exit code: 1

    Output directory does not exist¶

    $ aok visualize -i my-site.yaml -o /nonexistent/path/diagram

    ERROR    Output directory not found: /nonexistent/path

    Exit code: 1

    aok migration-convert¶

    Convert a Migration Tool draft site YAML into a Helm values file for the appian-platform-cs chart. The converter parses the input, validates it for non-standard or deprecated configurations, and emits a clean values file with inline comments and action annotations.

    aok migration-convert -i <draft-site.yaml> [-o <output-values.yaml>] [--debug]

    Options¶

    Option Short Required Description
    --input -i Yes Path to the Migration Tool draft site YAML file
    --output -o No Output Helm values file path (default: appian-platform-cs-values.yaml)
    --debug No Enable verbose diagnostic output (sets log level to DEBUG)

    What It Does¶

    1. Parses the Migration Tool draft site YAML (apiVersion crd.k8s.appian.com/v1beta1, kind Appian)
    2. Extracts site URL, version, HA mode, component replicas, engine overrides, data sources, and custom properties
    3. Partitions custom properties into enforced properties (mapped to dedicated Helm keys), SMTP configuration, and additional custom properties
    4. Validates the configuration, emitting warnings for non-standard replica counts, deprecated properties, unsupported JDBC drivers, etc.
    5. Emits a complete Helm values YAML with inline comments indicating what the user needs to update, what must not be changed, and what was detected as non-standard

    Example¶

    aok migration-convert -i migration-draft-site.yaml -o my-site-values.yaml

    Output on success:

      • conf.search-server.user.appian.password is now managed by the Operator from v0.181.0 and has been removed from the output.
  • Data source factories must be changed to org.apache.tomcat.jdbc.pool.DataSourceFactory with passwords provided via passwordSecretKeyRef.
Wrote my-site-values.yaml (2 warnings)

    Output File Structure¶

    The generated values file includes these sections in order:

    Section Description
    Header comment Generator version, chart reference
    Warnings block Bullet-pointed validation warnings (if any)
    siteName Empty placeholder — user must provide
    version Extracted from input — DO NOT CHANGE
    url Site URL from input
    staticUrl / dynamicUrl If present in input
    class Empty placeholder — user selects sizing class
    highAvailability Derived from zookeeper replicas — DO NOT CHANGE
    cascadeVersionToComponentTags Always true — DO NOT CHANGE
    passwordsPropertiesSecretName Only if SMTP auth is enabled
    metricsAuthToken If present in custom properties
    smtp SMTP configuration (if SMTP properties were present)
    additionalCustomProperties All non-enforced, non-SMTP, non-removed properties
    license Default license secret/configmap names
    storage Storage class and PVC placeholders
    images Image repository placeholders
    Component overrides Only for components with non-default values
    ingressTemplate Ingress configuration placeholder

    Validation Warnings¶

    The converter checks for and warns about:

    • Analytics shard count exceeding 3
    • MAX_EXEC_ENGINE_LOAD_METRIC exceeding 2145
    • Deprecated/removed properties (search-server password, RTS circuit breaker)
    • Component replica counts deviating from HA/non-HA defaults
    • Non-standard webapp, serviceManager, or engine override replica counts
    • Non-suite applicationContext
    • JDBC drivers not shipped with the platform (mysql, mysql:aws, db2)
    • Data source factory requiring migration to Tomcat pool

    Error Handling¶

    Scenario Behaviour
    Input file not found Prints error to stderr, exits with code 1
    Input file not readable Prints error to stderr, exits with code 1
    Invalid YAML syntax Prints error to stderr, exits with code 1
    Malformed version string Prints error to stderr, exits with code 1
    Output path not writable Prints error to stderr, exits with code 1

    Using --debug¶

    aok migration-convert -i draft-site.yaml --debug

    Enables DEBUG-level logging showing each step of the parse → validate → emit pipeline.
